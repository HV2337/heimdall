# Heimdall module interfaces

This document is the implementation contract for M2–M4. Implement modules against these names, types, signatures, ordering, and failure rules. Do not log raw prompts, retrieved records, patient values, API keys, token values, exception text, canaries, or decrypted vault content.

## 1. Shared contracts (`gateway/contracts.py`)

All dataclasses are frozen. Collections crossing module boundaries are tuples or read-only mappings. `Role` and `TokenType` are `Literal` types.

```python
from dataclasses import dataclass
from typing import Literal, Mapping, Protocol

Role = Literal["doctor", "nurse", "billing_clerk"]
TokenType = Literal[
    "PERSON", "PATIENT_ID", "PHONE", "EMAIL", "GOV_ID", "IP_ADDRESS",
    "API_KEY", "FILE_PATH", "SECRET", "DIAGNOSIS", "VITAL", "MEDICATION",
    "NOTE",
]

class SafeStageError(Exception):
    code: str
    def __init__(self, code: str) -> None: ...

class PolicyDenied(SafeStageError): ...  # deny decision; 403
class PolicyError(SafeStageError): ...    # policy/data fault; 503

@dataclass(frozen=True)
class RequestContext:
    request_id: str
    user_id: str
    role: Role
    session_id: str

@dataclass(frozen=True)
class NormalizedText:
    original: str
    clean_text: str
    matching_text: str

@dataclass(frozen=True)
class ScannableText:
    source: Literal["user_prompt", "retrieved_record"]
    record_id: int | None
    text: NormalizedText

@dataclass(frozen=True)
class ThreatAssessment:
    blocked: bool
    score: float
    source: Literal["user_prompt", "retrieved_record"] | None
    rule_code: str | None

@dataclass(frozen=True)
class SanitizedText:
    text: str
    entity_counts: Mapping[TokenType, int]

@dataclass(frozen=True)
class SanitizedRecord:
    fields: Mapping[str, str]
    entity_counts: Mapping[TokenType, int]

@dataclass(frozen=True)
class CheckedOutput:
    text: str

@dataclass(frozen=True)
class SessionRecord:
    session_id: str
    user_id: str
    expires_at_monotonic: float
    ttl_seconds: int

@dataclass(frozen=True)
class AuditEvent:
    timestamp_utc: str
    request_id: str
    session_id: str | None
    user_id: str | None
    role: Role | None
    decision: Literal["allow", "block"]
    blocking_stage: str | None
    status_code: int
    threat_score: float | None
    rule_code: str | None
    entity_counts: Mapping[TokenType, int]
    stage_latency_ms: Mapping[str, float]

@dataclass(frozen=True)
class PipelineRequest:
    api_key: str
    session_id: str
    prompt: str
    patient_ids: tuple[int, ...]
    requested_fields: tuple[str, ...] | None = None

@dataclass(frozen=True)
class PipelineResponse:
    request_id: str
    status_code: Literal[200, 403, 413, 503]
    answer: str | None
    message: str
    sanitized_prompt: str | None = None

@dataclass(frozen=True)
class PipelineDependencies:
    key_users: Mapping[str, tuple[str, Role]]
    patient_store: "PatientStore"
    patient_policy: "PatientPolicy"
    sessions: "SessionManager"
    classifier: "ThreatClassifier"
    vault: "TokenVault"

    timeout_seconds: float
    token_ttl_seconds: int
    session_ttl_seconds: int
    debug_trace: bool
```

`request_id` is generated by the orchestrator before authentication. `user_id` and `role` are populated only after API-key authentication. `session_id` is a random opaque value issued by the in-memory session manager, bound to `user_id`, and never accepted as authoritative unless that binding is checked. Use a new session ID for each isolated conversation. The `api_key` in `PipelineRequest` is never logged or copied into a context, response, or audit event.

## 2. Patient field treatment and sanitization policy

Every patient field is treated by the table below. `passthrough_after_free_text_pii_scan` means scan the text and replace detected PII/secrets with typed tokens, then pass only the remaining text. It never means pass detected PII raw. `generalize` is irreversible and its result is never stored in the vault.

| Patient field | Default treatment (`HEIMDALL_CLINICAL_MODE=0`) | Clinical mode (`HEIMDALL_CLINICAL_MODE=1`) |
| --- | --- | --- |
| `id` / API `patient_id` | `tokenize(PATIENT_ID)` | Same |
| `name` | `tokenize(PERSON)` | Same |
| `phone` | `tokenize(PHONE)` | Same |
| `dob` | `generalize(age_band, irreversible=true, not_stored_in_vault=true)` | Same |
| `ward` | `generalize(department, irreversible=true, not_stored_in_vault=true)` | Same |
| `diagnosis` | `passthrough_after_free_text_pii_scan` | `tokenize(DIAGNOSIS)` after scanning/tokenizing embedded PII |
| `vitals` | `generalize(vital_ranges, irreversible=true, not_stored_in_vault=true)` | `tokenize(VITAL)` after scanning/tokenizing embedded PII |
| `meds` / medication | `passthrough_after_free_text_pii_scan` | `tokenize(MEDICATION)` after scanning/tokenizing embedded PII |
| `billing_amount` | `generalize(billing_range, irreversible=true, not_stored_in_vault=true)` | Same |
| `notes` | `passthrough_after_free_text_pii_scan` | `tokenize(NOTE)` after scanning/tokenizing embedded PII |
| `created_at` / timestamps | `generalize(calendar_month, irreversible=true, not_stored_in_vault=true)` | Same |

The only supported values for `HEIMDALL_CLINICAL_MODE` are `0` and `1`; default is `0`. Any other value is a configuration error and startup fails closed. In clinical mode, free-text PII scanning happens first. Detected PII is emitted as its own typed marker; only the PII-free spans are put into a clinical-field token. Never nest a marker inside an encrypted clinical-field token, because nested tokens would bypass the output scanner.

Generalization methods are fixed: DOB becomes age bands `0–17`, `18–29`, `30–44`, `45–59`, `60–74`, or `75+` using the current UTC date; timestamps become `YYYY-MM`; billing amounts become `[0,999]`, `[1000,4999]`, `[5000,9999]`, `[10000,24999]`, or `[25000+]` in stored currency units; vitals become systolic/diastolic/pulse bands (`<90`, `90–119`, `120–139`, `140+`; `<60`, `60–79`, `80–89`, `90+`; `<50`, `50–59`, `60–99`, `100+` respectively); ward values map through the configured ward-to-department table and unknown values become `Other`. A malformed value that cannot be safely generalized raises `SanitizeError`; never fall back to the raw value.

`FIELD_TREATMENT` is a default table. `SanitizationPolicy` is the immutable runtime policy built from it and the clinical-mode flag:

```python
@dataclass(frozen=True)
class SanitizationPolicy:
    role_fields: Mapping[Role, frozenset[str]]
    field_treatments: Mapping[str, "FieldTreatment"]

@dataclass(frozen=True)
class TokenizeTreatment:
    token_type: TokenType

@dataclass(frozen=True)
class GeneralizeTreatment:
    method: Literal["age_band", "department", "vital_ranges", "billing_range", "calendar_month"]
    irreversible: Literal[True]
    not_stored_in_vault: Literal[True]

@dataclass(frozen=True)
class PassthroughTreatment:
    free_text_pii_scan: Literal[True]

FieldTreatment = TokenizeTreatment | GeneralizeTreatment | PassthroughTreatment
```

`field_treatments` contains the effective treatments after applying `HEIMDALL_CLINICAL_MODE`. Reject an unknown field or a record containing a field outside `role_fields[context.role]` before sanitizing it.

## 3. Token types and detokenization by role

Only these tokens are created: `PERSON`, `PATIENT_ID`, `PHONE`, and the free-text security/PII tokens `EMAIL`, `GOV_ID`, `IP_ADDRESS`, `API_KEY`, `FILE_PATH`, `SECRET`. With clinical mode enabled, also create `DIAGNOSIS`, `VITAL`, `MEDICATION`, and `NOTE`. Generalized values (`DOB`, `WARD`, `BILLING_AMOUNT`, timestamps, numeric ranges) are not vault tokens. No other token type may be emitted.

| Role | Token types that may be detokenized |
| --- | --- |
| `doctor` | `PERSON`, `PATIENT_ID`, `PHONE`; plus `DIAGNOSIS`, `VITAL`, `MEDICATION`, `NOTE` only when clinical mode is enabled |
| `nurse` | `PATIENT_ID`; plus `VITAL`, `MEDICATION` only when clinical mode is enabled |
| `billing_clerk` | `PERSON`, `PATIENT_ID`, `PHONE` |
| All roles | Never resolve `EMAIL`, `GOV_ID`, `IP_ADDRESS`, `API_KEY`, `FILE_PATH`, or `SECRET` |

`allowed_token_types(role, clinical_mode)` must return exactly this set. The patient-field policy remains independently enforced before retrieval and before sanitizing structured records.

## 4. Row-level patient authorization

`gateway/policy.py` references the existing M1 `PatientStore` from `gateway/data.py`. `PatientPolicy` is constructed with that store and exposes:

```python
class PatientPolicy:
    def __init__(self, patient_store: "PatientStore") -> None: ...
    def can_access_patient(self, context: RequestContext, patient_id: int) -> bool: ...
```

The M1 data layer has two assignment tables:

```sql
CREATE TABLE patient_assignments (
    user_id TEXT NOT NULL,
    role TEXT NOT NULL CHECK (role IN ('doctor', 'billing_clerk')),
    patient_id INTEGER NOT NULL REFERENCES patients(id),
    PRIMARY KEY (user_id, role, patient_id)
);

CREATE TABLE nurse_ward_assignments (
    user_id TEXT NOT NULL,
    role TEXT NOT NULL CHECK (role = 'nurse'),
    ward TEXT NOT NULL,
    PRIMARY KEY (user_id, ward)
);
```

Doctors and billing clerks are authorized only through an exact `(user_id, role, patient_id)` assignment. Nurses are authorized only when their `(user_id, ward)` assignment matches the patient's ward. The synthetic seed creates explicit doctor/clerk-to-patient assignments and nurse-to-ward assignments; it uses synthetic principal IDs and no credentials. Implement authorization with a parameterized `EXISTS` query that does not first fetch patient data. Return `False` for both an unassigned patient and a nonexistent patient. The orchestrator returns the same 403 status and exact body/message for both (`Request blocked.`); it must not reveal which case occurred. Database faults raise `PolicyError` and map to 503.

The orchestrator checks field-level policy and `can_access_patient(context, patient_id)` for every requested ID before retrieving any record. `PatientStore.get_patient` must repeat the row authorization in the retrieval query/transaction so assignment changes cannot create a check-then-read gap. A missing row after an authorization decision is also the same generic 403.

Field selection uses `allowed_fields(role: Role, requested_fields: tuple[str, ...] | None) -> tuple[str, ...]`. `None` returns every field permitted to that role in stable sorted order. Unknown roles, unknown fields, and forbidden fields raise `PolicyDenied` (403); assignment/database faults raise `PolicyError` (503).

The exact M1 adapter contract is `PatientStore(db_path)` from `gateway.data`:

```python
def get_patient(self, context: RequestContext, patient_id: int,
                fields: tuple[str, ...]) -> Mapping[str, object] | None: ...
def get_scan_identifiers(self, patient_id: int) -> tuple[str, ...]: ...
```

The store uses one SQLite connection per call and is safe for concurrent callers. `get_patient` returns only selected permitted fields or `None`, identical for missing and unassigned rows; database faults raise `PolicyError`. `get_scan_identifiers` returns only that patient's own name and phone for internal free-text scrubbing; these values must never reach callers, audit, or the LLM.

## 5. Sessions and HTTP contract (`gateway/main.py`)

Sessions are held in process memory, bound to the authenticated `user_id`, and expire a fixed duration after creation (not sliding). `HEIMDALL_SESSION_TTL_SECONDS` is a positive integer, default `3600`. Session creation, lookup, expiry, and deletion are protected by a lock. On expiry or deletion, call `vault.clear_session(session_id)` before discarding session state; if vault clearing fails, return 503 and do not proceed as if cleanup succeeded. The deployment must use one process until a shared session store is specified.

```python
class SessionAccessDenied(SafeStageError): ...  # missing, expired, or wrong owner; same public 403
class SessionStoreError(SafeStageError): ...    # internal store failure; 503

class SessionManager(Protocol):
    def create(self, user_id: str, ttl_seconds: int) -> SessionRecord: ...
    def require_owner(self, session_id: str, user_id: str) -> SessionRecord: ...
    def delete(self, session_id: str, user_id: str, vault: "TokenVault") -> None: ...
```

Concrete implementation: `InMemorySessionManager(clock: Callable[[], float])`; its injected monotonic clock enables deterministic expiry tests.

Session IDs are generated with a cryptographically secure random generator and are returned only by session creation. `require_owner` uses the same `SessionAccessDenied` for unknown, expired, and other-user sessions. `delete` has the same 403 behavior for those cases; on success it clears the vault then deletes the session.

`MAX_PROMPT_BYTES = 8192`. Measure `len(prompt.encode("utf-8"))` and reject a larger prompt before normalization, retrieval, or any LLM call. The HTTP response is 413 with `Request too large.` and an audit event with `blocking_stage="input_validation"`.

Endpoints:

| Method and path | Headers | Request | Success |
| --- | --- | --- | --- |
| `POST /v1/session` | `X-API-Key` | No body | `201`, JSON `{"session_id": "...", "expires_in_seconds": 3600}` |
| `POST /v1/chat` | `X-API-Key`, `X-Session-Id` | JSON `{"prompt": str, "patient_ids": [int, ...], "requested_fields": [str, ...] \| null}` | `200`, JSON containing `request_id`, `answer`, and `sanitized_prompt` |
| `DELETE /v1/session` | `X-API-Key`, `X-Session-Id` | No body | `204`, empty body |

Header names are case-insensitive per HTTP. Missing/invalid API key, absent/expired session, wrong session owner, row-policy denial, and threat/output-content blocks return `403` with the identical JSON body `{"detail":"Request blocked."}`. Operational stage errors return `503` with `{"detail":"Request could not be completed."}`. A too-large prompt returns the stated `413`. `POST /v1/session` authenticates the key before creating the session. `POST /v1/chat` authenticates the key, verifies that the session belongs to that user, then calls the pipeline. `DELETE /v1/session` authenticates the key, verifies ownership, clears the vault, and deletes the session.

`HEIMDALL_DEBUG_TRACE` accepts only `0` or `1`, default `0`. `PipelineResponse.sanitized_prompt` is `None` unless debug trace is enabled and sanitization has completed successfully. When present it contains only the sanitized user and permitted-record content; it never contains raw PII, decrypted token values, canary, system instructions, or unsanitized model input. Do not return it on a blocked response.

## 6. Errors and fail-closed behavior

Each module error below derives from `SafeStageError`; its constructor is `ErrorType(code: str) -> None`, with a stable non-sensitive code. `str(error)` returns only that code. Do not attach cause text, traceback locals, prompt text, patient data, credentials, token values, or dependency exception messages. Translate native exceptions and timeouts at each module's public boundary.

Authentication errors, `PolicyDenied`, session access denials, threat blocks, `OutputBlocked`, and input-size rejection are content/access denials (403, except input size 413). `PolicyError`, component faults, and timeouts are 503. The orchestrator writes a redacted audit event for every result. On failure, do not call the next stage and do not return partial model output. If audit writing itself fails, return 503 with no answer; do not claim the failed audit was written.

## 7. `gateway/normalize.py`

```python
class NormalizeError(SafeStageError): ...

def normalize_text(text: str) -> NormalizedText: ...
```

Apply Unicode NFKC and remove every Unicode `Cf` character to produce `clean_text` without decoding. Also decode suspicious segments into `matching_text` for detection only. A base64 candidate is at least 16 consecutive standard or URL-safe base64 characters, optionally ending with up to two `=` characters; pad it to a multiple of four and use the decoded text only if strict decoding produces valid UTF-8. A hexadecimal candidate is an even-length run of at least 12 hex digits; use it only if decoding produces valid UTF-8. Preserve input exactly in `original`. Detection uses `matching_text`; sanitization and LLM prompt construction use `clean_text`, never `original`. If a successfully decoded segment contains content that sanitization would tokenize or matches a deterministic threat rule, block at the threat stage with score `1.0` and `rule_code="encoded_sensitive_content"`. Non-string input or normalization faults raise `NormalizeError`.

## 8. `gateway/vault.py`

```python
class VaultError(SafeStageError): ...
class VaultExpiredToken(VaultError): ...
class VaultUnknownToken(VaultError): ...

class TokenVault(Protocol):
    def put(self, context: RequestContext, token_type: TokenType,
            value: str, ttl_seconds: int) -> str: ...
    def resolve(self, context: RequestContext, token: str,
                allowed_types: frozenset[TokenType]) -> str: ...
    def clear_session(self, session_id: str) -> None: ...
```

Concrete implementation: `InMemoryTokenVault(key: bytes, clock: Callable[[], float])`. The injected clock returns monotonic seconds for deterministic expiry tests. Constructor/key/storage/crypto faults raise `VaultError`; missing and expired marker lookups raise `VaultUnknownToken` and `VaultExpiredToken`.

Store only AES-GCM ciphertext in memory, with a fresh 12-byte nonce per stored ciphertext. `HEIMDALL_VAULT_KEY` is base64 encoding of exactly 32 random bytes; missing or malformed keys fail closed. Key records by `(user_id, session_id, token)` and enforce TTL with a monotonic clock. The vault is thread-safe: a lock protects encrypted entries, per-session counters, HMAC lookup indexes, expiry, and session clearing. Derive the lookup key as `HMAC-SHA256(vault_key, b"heimdall-vault-lookup-v1")`. Compute the lookup digest as HMAC-SHA256 over UTF-8 `user_id`, NUL, `session_id`, NUL, `TokenType`, NUL, and the canonical value. For the same canonical `(TokenType, value)` in the same session, `put` returns the same `[TOKEN_TYPE_n]` marker; across sessions markers are unlinkable. Store only the HMAC digest as the lookup key, never plaintext values outside AES-GCM ciphertext. `resolve` checks `allowed_types`; missing or expired entries raise the named vault errors. Key, crypto, lock/storage, and timeout faults raise `VaultError`. Never fall back to plaintext storage.

## 9. `gateway/sanitize.py`

```python
class SanitizeError(SafeStageError): ...

def sanitize_text(text: str, context: RequestContext, vault: TokenVault,
                  ttl_seconds: int, *,
                  known_names: tuple[str, ...] = ()) -> SanitizedText: ...

def sanitize_record(record: Mapping[str, object], context: RequestContext,
                    vault: TokenVault, ttl_seconds: int,
                    policy: SanitizationPolicy, *,
                    today: date | None = None) -> SanitizedRecord: ...
```

Both entry points consume `clean_text` (record string values are normalized before treatment) and return sanitized marker/generalized text only. `today` is injectable for deterministic age-band tests; omitted means current UTC date. `sanitize_record` raises `SanitizeError` for malformed inputs or policy, while vault errors propagate unchanged.

Before any detection or token insertion, neutralize every pre-existing marker-like substring matching `\[[A-Z][A-Z0-9_]*_[0-9]+\]` in both user text and record text by replacing the square brackets with fullwidth brackets (`［` and `］`). These caller-supplied strings must never be interpreted as vault references. Run free-text PII scanning before field treatment. Detect phone, email, government IDs, IP addresses, API keys, file paths, and known names; tokenize these findings with their actual `TokenType`. `known_names` contains only names in fields retrieved for the caller's role. Use vault deduplication so repeat occurrences of the same typed value in one session share a marker. `entity_counts` contains counts only, never values.

`sanitize_record` preserves the schema keys and returns string values in `SanitizedRecord.fields`. It rejects any field outside `policy.role_fields[context.role]` and applies `policy.field_treatments` exactly. Generalized values never call the vault. Passthrough text is free-text-scanned before being returned. In clinical mode, free-text PII markers are kept separate and only PII-free spans are tokenized as the field's clinical token type; never store nested markers inside a clinical token. Vault exceptions propagate unchanged; all other faults become `SanitizeError`.

## 11. `gateway/threat.py`

```python
class ThreatError(SafeStageError): ...

@dataclass(frozen=True)

    idf: tuple[float, ...]
    coefficients: tuple[float, ...]

```

The implementation class is `RuleAndModelClassifier(model: ThreatModel)`. Construction receives the portable model; `scan` raises `ThreatError` on runtime faults.

Run deterministic rules and the TF-IDF/logistic-regression classifier over every item, including both the user prompt and all retrieved records. Return the highest classifier score; ties use input order. Any rule block has score exactly `1.0`; its stable `rule_code` identifies the matched rule. Artifacts are portable JSON or NPZ only; never load pickle. JSON is UTF-8 with top-level keys `format`, `vocabulary`, `idf`, `coefficients`, `intercept`, `threshold`, `model_version`; `format` is `heimdall-tfidf-logreg-v1`; vocabulary indices are contiguous from zero; arrays have the vocabulary length and finite numeric values; threshold is in `[0.0, 1.0]`. Load NPZ with `allow_pickle=False`. Train the model on the big-endian LinuxONE VM and save held-out metrics with the artifact.

## 15. `gateway/main.py` orchestrator and HTTP layer

```python
MAX_PROMPT_BYTES = 8192

def build_dependencies(settings: Settings) -> PipelineDependencies: ...

def run_pipeline(request: PipelineRequest,
                 dependencies: PipelineDependencies) -> PipelineResponse: ...
```

`build_dependencies` wires configured stage objects and raises a safe startup/configuration error on failure. `InMemorySessionManager(clock: Callable[[], float])` is the in-memory session implementation; the injected monotonic clock makes TTL behavior deterministic. `sanitize_record(..., today: date | None = None)` likewise accepts the UTC date used for age-band generalization; omitted means current UTC date.

`PipelineDependencies.key_users` maps SHA-256 API-key digests to `(user_id, role)`, never plaintext keys. `PipelineRequest.session_id` must be owned by the authenticated user. Execute exactly this pipeline order:

1. Generate `request_id`; authenticate API key; resolve session ownership; construct `RequestContext`.
2. Measure prompt UTF-8 byte length and enforce `MAX_PROMPT_BYTES` before normalization, retrieval, or LLM calls.
3. Resolve field-level `allowed_fields`; check `can_access_patient(context, patient_id)` for every requested ID. Do both before retrieving any records.
4. Retrieve only role-permitted fields. A false authorization or missing row returns identical 403 response/event.
5. Normalize prompt and each retrieved record; scan `matching_text`, but sanitize and build the LLM prompt from `clean_text`.
6. Scan normalized user prompt and all retrieved record text with rules and classifier. A decoded sensitive or threat-triggering segment blocks at this stage with `rule_code="encoded_sensitive_content"`; a rule-only block has score `1.0`.
7. Sanitize prompt and structured records with the same `RequestContext`, vault, TTL, `SanitizationPolicy`, and only role-permitted `known_names`.
8. Build the LLM prompt from fixed system instructions, a per-request canary, sanitized user text, and sanitized permitted records. Never include `original` text.
9. Call LLM with `timeout_seconds`.
10. Check output before detokenization. `OutputBlocked` returns 403 at `output_control`; `OutputControlError` returns 503.
11. Detokenize only the role/mode-allowed tokens.
12. Write allow audit event; return status 200, answer, and optional debug trace.

Prompt over limit returns status 413, `answer=None`, `sanitized_prompt=None`, message `Request too large.`, and an audit event at `input_validation`. Access/content denials return status 403, `answer=None`, `sanitized_prompt=None`, message `Request blocked.`. Component faults and timeouts (database, normalization, sanitizer, vault, classifier, LLM, output scanner, audit) return status 503, `answer=None`, `sanitized_prompt=None`, message `Request could not be completed.`. Audit every denial/fault with safe identifiers and counts. If audit fails, return 503 and no answer.

`PipelineResponse.sanitized_prompt` is populated only when `HEIMDALL_DEBUG_TRACE=1` and sanitization completed successfully; otherwise it is `None`. When present it contains only sanitized user text and sanitized permitted records. It excludes raw values, decrypted tokens, canary, system instructions, and model output. It is always `None` on blocked/fault responses.

HTTP contracts:

| Method/path | Required headers | Request body | Success response |
| --- | --- | --- | --- |
| `POST /v1/session` | `X-API-Key` | None | `201`, `{"session_id": "<opaque>", "expires_in_seconds": <int>}` |
| `POST /v1/chat` | `X-API-Key`, `X-Session-Id` | `{"prompt": str, "patient_ids": [int, ...], "requested_fields": [str, ...] or null}` | `200`, request ID, answer, and optional `sanitized_prompt` |
| `DELETE /v1/session` | `X-API-Key`, `X-Session-Id` | None | `204`, empty body |

HTTP header matching is case-insensitive. Session creation authenticates the key, creates a random session bound to the resulting `user_id`, and returns its TTL. Chat authenticates the key and checks the session owner before running the pipeline. Delete authenticates, checks ownership, calls `vault.clear_session(session_id)`, then deletes session state. Unknown, expired, and wrong-owner sessions share the same 403 body `{"detail":"Request blocked."}`. Operational faults return `{"detail":"Request could not be completed."}` with 503. The existing `GET /health` remains independent of the pipeline.
